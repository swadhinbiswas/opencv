# CV Builder Research Summary

## 1. Top CV Builder Repos README Patterns

### RenderCV (17.3k stars)
**Key elements:**
- **Clear value proposition**: "Resume builder for academics and engineers"
- **Badges**: Tests, coverage, docs, PyPI version, downloads
- **Simple getting started**: 3-step process (install, create, render)
- **Visual examples**: Multiple theme screenshots with clickable PDFs
- **Feature highlights**: JSON schema, design options, validation, multilingual support
- **AI integration**: Agent skill for AI coding assistants
- **Code examples**: YAML input → PDF output transformation

### JSON Resume (Community-driven)
**Key elements:**
- **Standardization focus**: "JSON-based standard for resumes"
- **Ecosystem approach**: Monorepo with apps, packages, themes
- **Clear architecture**: Table layout showing apps/packages/URLs
- **Quickstart commands**: Clone, install, dev server
- **Testing instructions**: Unit tests, e2e tests
- **Theme development guide**: How to build custom themes
- **AI features**: Job recommendations, cover letters, interview simulation
- **Contributing guide**: Fork, branch, PR workflow

### McDowell CV (LaTeX)
**Key elements:**
- **Screenshot preview**: Visual example of output
- **Use cases**: Links to tools using the class
- **Class options**: Font customization
- **Command reference**: `\name`, `\address`, `\contacts`, etc.
- **Build instructions**: Clear lualatex commands

## 2. CV Writing Best Practices (2024-2026)

### Core Principles
1. **Tailor each resume to the job** - Customize for every application
2. **Use keywords from job descriptions** - Mirror the language used
3. **Quantify accomplishments** - Numbers, metrics, percentages
4. **Start bullet points with action verbs** - "Designed", "Launched", "Synthesized"
5. **Include job title in headline** - 10.6x more interviews (Jobscan data)

### Bullet Point Formula
**Bad**: "Worked with engineering to fix bugs"
**Good**: "Prioritized a backlog of 50+ tickets, reducing critical app crashes by 22% in Q3"

**Structure**: Action verb + What you did + Measurable result

### Skills Strategy
- **Hard skills**: Technical, job-specific (Python, SQL, AWS)
- **Soft skills**: Interpersonal (communication, leadership)
- **76.4% of recruiters** filter by skills first
- Include skills in dedicated section AND bullet points

## 3. ATS (Applicant Tracking System) Best Practices

### Formatting Rules
1. **Standard dates**: Use "MM/YYYY" or "Month YYYY" format
2. **Web-safe fonts**: Arial, Calibri, Georgia, Helvetica
3. **No headers/footers**: Keep contact info in main body
4. **Traditional section headings**: "Work Experience", "Education", "Skills"
5. **Single-column layout**: Avoid multi-column designs
6. **No graphics/tables**: Text only for maximum compatibility

### Common ATS Mistakes
- ❌ "Jan '21 – Mar '23" (apostrophes confuse ATS)
- ❌ Custom fonts or icons (become [NULL] or gibberish)
- ❌ Creative section titles ("My Journey" instead of "Work Experience")
- ❌ Multi-column layouts (scrambles reading order)
- ❌ Text boxes and headers/footers (invisible to parsers)

### Keyword Optimization
- Include exact job title from posting
- Use keywords naturally in bullet points
- Avoid "keyword stuffing" - recruiters notice
- Match rate of 75%+ is recommended
- Tailor keywords for specific ATS platforms (Lever, Greenhouse, Taleo)

## 4. Community-Focused Open Source README

### Best-README-Template Structure (16.3k stars)
**Essential sections:**
1. **Project shields/badges** - Contributors, forks, stars, issues, license
2. **Logo and tagline** - Clear visual identity
3. **Table of contents** - Collapsible, linked sections
4. **About the project** - Problem it solves, why it exists
5. **Built with** - Major frameworks/libraries
6. **Getting started** - Prerequisites, installation steps
7. **Usage** - Code examples, screenshots
8. **Roadmap** - Planned features, known issues
9. **Contributing** - Fork, branch, commit, PR workflow
10. **License** - Clear licensing info
11. **Contact** - Author info, project link
12. **Acknowledgments** - Credits and resources

### Community Engagement Elements
- **Top contributors section** - Recognizes active participants
- **Clear contribution guidelines** - Step-by-step process
- **Issue templates** - Bug reports, feature requests
- **Discussions** - For questions and ideas
- **Code of Conduct** - Expected behavior
- **Security policy** - How to report vulnerabilities

### README Best Practices
- **Keep it concise** - Under 200 lines preferred
- **Use visual hierarchy** - Headers, badges, screenshots
- **Provide quickstart** - Get running in <5 minutes
- **Include examples** - Show, don't just tell
- **Link to detailed docs** - Don't overload README
- **Use badges** - CI status, coverage, version, downloads
